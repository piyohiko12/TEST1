asyncioは、1つのスレッド上でタスクを切り替えながら並行処理を行う仕組みです。核心は「待ち時間の間に別の仕事を進める」こと。`await`で待機を宣言すると、その処理がI/O完了などを待つ間、制御がイベントループに戻り、実行可能な別のコルーチンが動きます。CPUを止めて眠るのではなく、待っている隙間を他の仕事で埋めるイメージです。

スレッドとの最大の違いは、切り替えのタイミングと主体です。スレッドはOSが任意のタイミングで割り込んで切り替える(プリエンプティブ)ため、いつ中断されるか予測できず、共有データの保護にロックが要ります。asyncioは`await`と書いた箇所でしか切り替わらない(協調的)ので、中断点が明示的でロック競合が起きにくく、デバッグしやすい。一方、`await`のない重い計算を書くと、その間ループ全体が固まります。また、asyncioは基本1スレッドなのでCPUコアを1つしか使えませんが、スレッドは複数あってもPythonのGIL(グローバルインタプリタロック)のせいで純粋な計算では並列化されません。真の並列計算が必要なら`multiprocessing`が適します。

使い分けの基準は、処理がI/O待ち中心かCPU計算中心かです。ネットワークリクエスト、DBアクセス、ファイル読み書きなど「待ち」が支配的で、かつ大量の接続を同時にさばきたいならasyncioが向きます。数個のブロッキング処理を並行させたいだけなら`ThreadPoolExecutor`のほうが手軽で、既存の同期ライブラリもそのまま使えます。CPUを使い切る計算はプロセス並列です。

```python
import asyncio

async def fetch(name, delay):
    print(f"{name} 開始")
    await asyncio.sleep(delay)  # I/O待ちを模擬。この間に他が動く
    print(f"{name} 完了")
    return name

async def main():
    results = await asyncio.gather(
        fetch("A", 2),
        fetch("B", 1),
    )
    print(results)

asyncio.run(main())
```

この例では合計3秒ではなく約2秒で終わります。`await asyncio.sleep`の待ち時間が重なって進むためで、これがasyncioの並行性の本質です。
