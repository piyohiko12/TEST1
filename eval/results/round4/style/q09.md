asyncioは、1つのスレッド内で複数のタスクを協調的に切り替えて動かす仕組みです。ネットワーク通信やファイル待ちのような「待ち時間」が多い処理を効率化するために使います。

## 基本的な仕組み

中心にあるのは**イベントループ**です。`async def`で定義した関数(コルーチン)は、内部で`await`にぶつかると「ここで待ちが発生するので、他の処理を進めていいですよ」と制御をイベントループに返します。ループは待ちが解けたタスクを見つけて再開させる、という切り替えを繰り返します。

```python
import asyncio

async def fetch(name, sec):
    print(f"{name} 開始")
    await asyncio.sleep(sec)  # ここで制御を手放す
    print(f"{name} 完了")

async def main():
    await asyncio.gather(fetch("A", 2), fetch("B", 1))

asyncio.run(main())
```

`asyncio.sleep`の待ち時間中に他方が動くので、全体は2秒強で終わります(逐次なら3秒)。重要なのは、切り替えが起きるのは`await`の地点だけだという点です。プログラマが明示した箇所でしか譲らないので、これを**協調的マルチタスク**と呼びます。

## スレッドとの違い

スレッドはOSが任意のタイミングで強制的に切り替える(プリエンプティブ)のに対し、asyncioは`await`でしか切り替わりません。この違いから、asyncioは競合状態が起きにくくデバッグしやすい反面、途中に`await`のない重い計算を挟むとそこで全体が止まります。

また、CPythonにはGIL(グローバルインタプリタロック)があるため、スレッドを使ってもPythonバイトコードは実質同時に1つしか動きません。つまりCPUをフル回転させる計算の並列化には、スレッドもasyncioも向いておらず、`multiprocessing`が必要です。

## どう使い分けるか

判断軸は「何を待っているか」です。

- **I/O待ちが多い** — 多数のHTTPリクエスト、DBアクセス、WebSocketなど。asyncioが最適で、数千の接続を1スレッドで捌けます。
- **CPU計算が重い** — 画像処理、数値計算、暗号化など。`multiprocessing`を使います。
- **既存の同期ライブラリを並行化したい** — asyncio非対応のブロッキングなライブラリしかない場合は、スレッドプール(`concurrent.futures.ThreadPoolExecutor`)のほうが手軽です。

asyncioの効果は、対象のライブラリが非同期対応(`aiohttp`、`asyncpg`など)であって初めて発揮されます。普通の`requests`を`await`しても並行にはならない点に注意してください。
