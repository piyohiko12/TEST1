# 検証記録

判定方法: 各ラウンドで `style`(Opus 4.8+プロンプト)を `refstyle`(Fable 5+同一プロンプト=目標)と質問ごとに突き合わせ、固定チェックリストで判定する。
- **結論先行**: 第一文が直接の答えか
- **長さ比**: styleの文字数 ÷ refstyleの文字数(○=1.3以下 / △=1.7以下 / ×=1.7超)
- **構造一致**: 散文/箇条書き/見出しの選択がrefstyleと一致するか(太字小見出し+段落の羅列も列挙構造と見なす)
- **末尾規律**: 再要約・社交的な招待・「ちなみに」余談を付けていないか
- **取捨選択**: 代替手段・OS分岐・頼まれていない助言を網羅していないか

---

## ラウンド1(プロンプトv1)

### 対照実験の前提データ

- `ref`(素のFable 5)は`base`(素のOpus)と同様に冗長・構造過多(平均1,540字、見出し・表・絵文字・末尾社交辞令あり)。**スタイルはプロンプト由来**である(詳細は fable5-analysis.md)。
- v1はOpusに対して構造面で大きく効いている: `base`の見出し・表・複数方法の列挙はほぼ解消。結論先行は8/8で達成。

### 発見した乖離パターン(v2で対処するもの)

1. **長さが平均1.85倍**(1.5〜2.5倍)。v1は構造は矯正するが分量を圧縮できていない。`base`比でもq7・q8はむしろ増えた。
2. **末尾の招待質問**(q4「どんなサービスか教えてください」、q5・q8同型)。refstyleは答えを出し切った質問では聞き返さない(8問中q7のみ、しかも条件付き)。
3. **末尾の再要約**(q3「要するに〜」)。冒頭の結論を言い直している。
4. **擬似列挙**(q3・q8)。「**太字見出し** 段落」の羅列で、散文指定をすり抜けて列挙構造を維持している。
5. **網羅癖**(q6でssh-agent手順+3OS分のクリップボードコマンド、q1で頼まれていない暗記アドバイス、q2で「ちなみに」の余談)。refstyleは代表的な1経路だけ示し、代替は括弧内1句で済ませる。

### v2の改訂方針

- 「迷ったら短く。読者は続きをいつでも聞ける」という判断原理を冒頭に追加(網羅癖の根は「読者が困るかも」という保険であるため、保険が不要な理由を与える)
- 取捨の定量基準: 方法・経路は代表1つ、代替・分岐は1文まで/事実質問1〜2文・解説2〜3段落の目安
- 末尾規律の明文化: 再要約禁止・「ちなみに」禁止・答えを出し切った後の招待質問禁止
- 擬似列挙の穴を塞ぐ: 太字小見出しの羅列も列挙と定義
- コード依頼の応答例を追加(コード先行+補足1文で終わる形)
