# Fable 5 出力特性の調査

調査日: 2026-07-18 / 方法: claude CLI 経由で `claude-fable-5` と `claude-opus-4-8` を同一条件で呼び出した実測(`eval/results/`)。公式発表ページ・解説記事はネットワークポリシーで取得不可だったため、実測を一次情報とする。

## 最重要の発見: 「Fable 5らしさ」はスタイル指示への追従性である

素のFable 5(中立システムプロンプトのみ)は、Opus 4.8と同様に冗長で構造過多な出力をする。

| 質問 | 素のFable 5 | Fable 5+スタイルプロンプト |
|---|---|---|
| q1 光速 | 327字。太字+「ちなみに」の追加雑学 | **51字。一文で回答** |
| q3 HTTP/HTTPS | 1,617字。見出し5個+比較表+絵文字+「お気軽にどうぞ!」 | 568字。散文2段落 |
| q6 SSHキー | 2,162字。全OS網羅+ssh-agent+補足 | 1,022字。必須3手順+注意1点 |

素のFable 5は末尾の社交辞令(「何か具体的に知りたい点があれば、お気軽にどうぞ!」)すら書く。つまりユーザーが体験する「Fable 5らしい簡潔な応答」は、モデル固有の性質ではなく、**システムプロンプトのスタイル指示を高精度に実行する能力**から生まれている。

### プロジェクトへの帰結

- 目標(参照)は「素のFable 5」ではなく「**Fable 5+本プロンプト**」の出力(`refstyle`アーム)である。
- 改善課題は「Opusに簡潔さを教える」ことではなく、「**同じ指示を与えたときにOpusが崩すポイント**」を特定し、その崩し方をピンポイントで禁止・矯正することである。

## Fable 5がスタイル指示を実行するときの具体的な挙動(refstyle実測)

1. **長さ**: 内容に応じて51字〜1,022字まで大きく変える。単純な質問への回答は徹底して短い。
2. **結論先行**: 第一文が常に直接の答え(「約30万km/sです」「実は俗説で〜」「迷うならPostgreSQLをおすすめします」)。
3. **散文優先**: 解説は段落のみで書く。箇条書き・小見出しは手順(q6)のみ。比較(q4)でも散文を維持した。
4. **詳細の取捨**: 代表的な1つの方法・1つのパスだけ示す。OS別の分岐や代替手段は1文の言及か省略(q6でssh-agent手順を丸ごと省略、クリップボードは`cat`+括弧内で`pbcopy`に触れるだけ)。
5. **末尾**: 答えが出たら終わる。追加情報の要求は、それで答えが実際に変わる場合のみ(q7の「状況を教えてもらえれば一緒に整理します」)。答えを出し切った質問(q4)では聞き返さない。
6. **繰り返さない**: 冒頭で述べた結論を末尾で再要約しない。
7. **訂正先行**(q2): 「実は俗説で〜」と第一文で訂正し、それから仕組みを説明。
8. **感情への応答**(q7): 共感は1文、すぐ実質(何をすべきか・何を提供できるか)へ移る。過剰な励ましの羅列をしない。
